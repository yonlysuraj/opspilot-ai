
You are a Senior AI Engineer, Agentic AI Architect, and Full-Stack Developer.

I want you to build a production-oriented, portfolio-grade Enterprise Agentic AI Automation Platform called "OpsPilot AI".

IMPORTANT:
This is a real working project, not a tutorial or a collection of mock UI screens. Implement the actual application step by step, with clean, maintainable code, working APIs, and automated tests.

PROJECT OBJECTIVE

Build an intelligent enterprise AI assistant that can understand a user's request, plan tasks, retrieve knowledge, interact with enterprise tools through MCP, execute safe operations, request human approval for sensitive actions, and show execution history through a web dashboard.

Example user request:

"Find my overdue engineering tickets, check related project documents, identify blockers, and prepare follow-up messages for responsible team members."

The AI should:
1. Understand the request.
2. Decide which tools are needed.
3. Query the appropriate MCP tools.
4. Retrieve relevant document context.
5. Analyze the results.
6. Prepare actionable recommendations.
7. Draft follow-up messages.
8. Request approval before performing sensitive actions.
9. Display the execution trace in the dashboard.

TECHNOLOGY STACK

Backend:
- Python 3.11+
- FastAPI
- LangGraph for agent workflows and state management
- LangChain where useful
- Official MCP Python SDK for tool servers and clients
- Pydantic for structured data
- SQLite for initial persistence

AI:
- Ollama running locally
- An available free local model that supports tool calling
- Local embedding model
- ChromaDB for document retrieval
- No paid AI APIs

Frontend:
- React + Vite
- TypeScript
- Tailwind CSS
- Clean SaaS-style responsive dashboard

Engineering:
- Docker and Docker Compose where practical
- Pytest
- GitHub Actions CI
- Structured logging
- Environment-based configuration
- Clear documentation

COST REQUIREMENT

The complete local MVP must run at zero subscription/API cost.

Never require OpenAI API credits, Anthropic API credits, paid cloud hosting, or paid external services.

Ollama should run locally. Detect whether the requested model is available and provide clear setup instructions if it is missing.

Do not assume the user has a GPU. Offer smaller model choices suitable for CPU-only development, and explain performance limitations.

CORE MODULES

MODULE 1 — AGENT ORCHESTRATION

Implement a LangGraph agent that can:
- Interpret user instructions
- Select appropriate tools
- Execute multi-step workflows
- Handle tool errors
- Maintain conversation context
- Return structured final results
- Request approval before sensitive actions

Use bounded tool iterations, timeouts, and error handling.

MODULE 2 — MCP TOOL INTEGRATION

Build a working MCP server exposing enterprise-style tools:

- list_tasks
- get_task_details
- search_documents
- get_project_status
- create_followup_draft
- propose_task_update

Start with realistic, clearly labeled local demo data for projects, employees, documents, and tickets.

The tools must execute real operations against the local datastore, not return static hardcoded responses.

Use an actual MCP client-server connection. Do not simply call ordinary Python functions while claiming they are MCP tools.

Design the integration so that real GitHub, Jira, and email connectors can be added later.

MODULE 3 — ENTERPRISE KNOWLEDGE RETRIEVAL

Implement document upload and retrieval with:
- PDF and TXT support
- Document parsing
- Chunking
- Local embeddings
- ChromaDB
- Semantic search
- Source references in responses

Keep this module small and functional. The main focus of the project is agentic execution.

MODULE 4 — HUMAN APPROVAL

Implement a durable approval workflow.

The agent must not directly execute sensitive or external write operations.

Instead:
- Generate a proposed action
- Store the proposal with its arguments
- Pause execution for approval
- Show the action in the dashboard
- Allow Approve or Reject
- Resume the workflow safely

Rejected actions must never execute.

Include safeguards against duplicate execution and unauthorized tool access.

MODULE 5 — AI DASHBOARD

Build these views:

1. Overview
   - Agent executions
   - Successful and failed runs
   - Pending approvals
   - Recent activity

2. Agent Workspace
   - Chat interface
   - Tool execution status
   - Final answers and citations

3. Workflow Trace
   - Agent steps
   - Tools invoked
   - Execution status
   - Latency and errors

4. Approval Center
   - Pending actions
   - Approve and Reject controls
   - Approval history

5. Knowledge Base
   - Upload documents
   - List indexed documents
   - Search indexed content

Use a clean and professional interface suitable for a GitHub portfolio demonstration.

MODULE 6 — OBSERVABILITY AND EVALUATION

Record:
- Execution ID
- Tool name
- Start and end timestamps
- Execution duration
- Status
- Error details
- Approval decisions

Add a small automated evaluation dataset containing realistic enterprise requests.

Test:
- Correct tool selection
- Tool execution
- Retrieval relevance
- Approval enforcement
- Error handling

Do not invent performance metrics. Display only measured results.

SECURITY REQUIREMENTS

- Never expose secrets in source code.
- Provide .env.example.
- Never execute arbitrary shell commands requested by the agent.
- Treat uploaded documents and tool outputs as untrusted data.
- Prevent retrieved text from overriding system instructions.
- Validate tool inputs with Pydantic.
- Require explicit approval before external changes.
- Do not execute untrusted generated code.
